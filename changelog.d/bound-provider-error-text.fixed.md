- A `MembraneError` no longer carries a provider's whole error body. Some providers echo the entire rejected request in their error response (one OpenAI-compatible 400 returned ~1.7 MB), and that text used to become the error's `message`, its stack and its `rawError`, and so every log line, `onError` payload and agent-facing failure notice built from the error. The constructor now bounds what every adapter, SSE error frame, SDK error and membrane rethrow passes through it:
  - `message` is capped at 2,000 characters: its head and tail around a marker stating how many of how many characters were omitted. A message within the cap is unchanged, bounding is idempotent, and neither cut splits a surrogate pair. A freshly constructed error's `stack` starts with `MembraneError: ` and that bounded message, then the runtime's ordinary frame lines. A `message` that isn't a string (from a JavaScript caller) is converted to text first, as `Error` converts one, rather than failing the constructor.
  - `rawError` is bounded to 16 KiB of UTF-8 JSON, measured in aggregate (nested bodies, headers and enumerable fields all count). A value within the bound is unchanged. Beyond it, a summary replaces it: `{ truncated, bytes | jsonBytes, sha256, head }`, so an identical body stays recognizable by its hash without being kept. A cyclic value becomes its acyclic JSON form, and a value that cannot be serialized becomes a short description.
  - Reading an `Error` for `rawError` is guarded field by field: a property whose getter throws is recorded as `[unreadable: …]`, so describing a hostile error can no longer replace the failure being reported. `classifyError`'s reads of an error (whether it is an `Error`, its name, message and socket codes) are guarded the same way.
  - `providerErrorCode` is capped at 128 characters. Longer, provider-supplied codes keep their first 64 characters and their length. A code that isn't a string is kept as its string form.
  - `serializeError` bounds the `message` and `stack` it copies, also when an `Error` carries them as own enumerable properties, and still leaves the stack out in production. Its whole result, for any value it is given, is held to the same 16 KiB aggregate bound as `rawError`, so what a host records through it, and the `rawError` that `classifyError` returns (an `onError` hook's included), are bounded too; the name and every copied field count toward it. An `Error` held in one of the copied fields is serialized the same way, so its text counts toward the bound instead of hiding behind JSON's `{}`.
  - The cache keepalive bounds the error text it emits itself (its `error` event and the `disabled` reason): a refused poke reaches it as the SDK's or the host's error, which never passed through the constructor. Its call receipt keeps the error as thrown; record it with `serializeError`.
- `type`, `retryable`, `httpStatus`, `retryAfterMs` and the classification itself are decided before construction. For errors the adapters produce, retry counts, the overload schedule and the stream abort disposition decide exactly as they do for the same failure with a small body (regressions with ~1 MB echoes containing "rate", "529", "overloaded_error", "abort" and "aborted"), because #56 decides those by status and by type. One exception remains: a status-less error whose message carries an overload token only in its omitted middle no longer selects the overload schedule. That is any error classified from its text alone, such as a thrown `Error` or an SSE error frame that states no status and no overload type. The omission marker's own counts are never read as an overload token. On a tree without #56, those consumers search the message text itself.
- Verified with scripted fetch, SDK, Bedrock and SSE responses only; no live provider calls.
