- A `MembraneError` no longer carries a provider's whole error body. Some providers echo the entire rejected request in their error response (one OpenAI-compatible 400 returned about 1.7 MB), and that text became the error's `message` and `rawError`, and so every log line, `onError` payload and agent-facing failure notice built from it.
  - Its `message` keeps at most 2,000 characters: the head and tail around a marker saying how many of how many characters were left out, never splitting a surrogate pair. A message within the bound is unchanged. `classifyError` bounds the message it returns the same way, and still classifies by the whole text.
  - Its `rawError`, when its JSON passes 16 KiB of UTF-8, is replaced by `{ truncated, bytes | jsonBytes, sha256, head }`, so an identical body stays recognizable by its hash. Within the bound, or with no JSON form, it is kept as given. `classifyError` bounds the `rawError` it returns the same way.
  - The cache keepalive bounds the error text it emits, its `error` event and its `disabled` reason. Its call receipt keeps the error as thrown.
  - A retryable error with no HTTP status, other than a network failure or a timeout, whose `529` or `overloaded_error` sits only in the omitted middle of a message longer than the bound no longer takes the overload retry schedule. A whole marker's counts are never read as one.
- A wait stated in prose ("retry after N seconds") is read only from the provider's own message: the message the body gives, in any of the shapes membrane reads one from (a `message` or `Message` field, a `detail`, a string `error`, or the message of the first entry in a top-level `errors` list), or the caller's message when the body is absent or `null`. It's no longer read from the SDK's rendering of the body, from membrane's rendering of a Bedrock stream error event, or from a body that gives no message, any of which can echo the request. A body that isn't JSON counts as the provider's message, so a wait stated in it is still read.
- A Bedrock stream `error` event is read as the error's body, as the Anthropic adapter reads the same event from Anthropic's API: its message is the provider's message, and a `code` or a retry field in it counts as it does there. Before, only its error type, taken as the code, and membrane's rendering of the event were read. A stream exception with its own message passes `{ message }` as the body, so that message is read without membrane's `Bedrock stream error (…): ` prefix.
- A `null` body counts as no body in classifying an error too, so the caller's message is read for it, as when the body is absent. A 400 with a `null` body and the message "prompt is too long: 250000 tokens > 200000 maximum" was `invalid_request`, and is now `context_length`.
