- A `MembraneError` no longer carries a provider's whole error body. Some providers echo the entire rejected request in their error response (one OpenAI-compatible 400 returned ~1.7 MB), and that text used to become the error's `message`, its stack and its `rawError`, and so every log line, `onError` payload and agent-facing failure notice built from the error. The constructor now bounds what every adapter, SSE error frame, SDK error and membrane rethrow passes through it:
  - `message` is capped at 2,000 characters: its head and tail around a marker stating how many of how many characters were omitted. A message within the cap is unchanged, bounding is idempotent, and neither cut splits a surrogate pair. A freshly constructed error's `stack` starts with that bounded message and additionally carries the runtime's ordinary frame lines.
  - `rawError` is bounded to 16 KiB of UTF-8 JSON, measured in aggregate (nested bodies, headers and enumerable fields all count). A value within the bound is unchanged. Beyond it, a summary replaces it: `{ truncated, bytes | jsonBytes, sha256, head }`, so an identical body stays recognizable by its hash without being kept. A cyclic value becomes its acyclic JSON form, and a value that cannot be serialized becomes a short description.
  - Reading an `Error` for `rawError` is guarded field by field: a property whose getter throws is recorded as `[unreadable: …]`, so describing a hostile error can no longer replace the failure being reported.
  - `providerErrorCode` is capped at 128 characters. Longer, provider-supplied codes keep their first 64 characters and their length.
  - `serializeError` bounds the `message` and `stack` it copies, also when an `Error` carries them as own enumerable properties, and still leaves the stack out in production.
- `type`, `retryable`, `httpStatus`, `retryAfterMs` and the classification itself are decided before construction. For errors the adapters produce, retry counts, the overload schedule and the stream abort disposition decide exactly as they do for the same failure with a small body (regressions with ~1 MB echoes containing "rate", "529", "overloaded_error", "abort" and "aborted"), because #56 decides those by status and by type. One exception remains: a status-less error built by hand whose message carries an overload token only in its omitted middle no longer selects the overload schedule. On a tree without #56, those consumers search the message text itself.
- Verified with scripted fetch, SDK, Bedrock and SSE responses only; no live provider calls.
