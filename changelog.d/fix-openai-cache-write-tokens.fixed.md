- `OpenAIResponsesAPIAdapter` now reads `usage.input_tokens_details.cache_write_tokens` into `usage.cacheCreationTokens`, so a prompt-cache write on OpenAI's Responses API leaves `inputTokens` under the cache-inclusive normalization and is priced on its own: every built-in OpenAI row carries `cacheWritePerMillion` — 1.25× input from GPT-5.6 on, the guide's rate for the 30-minute cache, and the input rate on earlier models, which charge nothing extra. So `estimatedCost.cacheWrite` is now a number (0 when nothing was written) for every OpenAI call priced by a built-in row, where it was undefined. A caller's own `ModelRegistry` row for an OpenAI model needs a write rate too, or `calculateCost` — which prices no cache token without a rate, by design — leaves the writes unpriced; the `ModelPricing` doc says so. Before this change the field was not read, so a write was counted and priced as ordinary input and the GPT-5.6+ premium was missing from `estimatedCost`.
