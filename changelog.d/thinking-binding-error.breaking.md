- **Consumers that switch exhaustively on `MembraneErrorType`, or act on `invalid_request`:** the public `MembraneErrorType` union gains a member, `thinking_binding`, for a 400 refusing a signed thinking block the request sent back ("Invalid `signature` in `thinking` block…"), which used to be typed `invalid_request`. Anthropic sends it for a block bound to a different conversation, or sent after what came before it changed (its block binding: seen live under `prefix_mismatch_behavior: "error"`, while under the default one account saw this 400 and another a silent drop), and for a block whose signature was altered, under every behavior. A `redacted_thinking` block's refusal is matched the same way, by analogy; it hasn't been seen. The request is well formed, and the error isn't retryable as it stands. **Who needs to act:** any code with an exhaustive `switch` over `MembraneErrorType`, or a `Record<MembraneErrorType, …>` lookup, which TypeScript now reports; and any consumer that acts on `invalid_request` as a malformed request, such as a breaker that sheds history over it, which no longer sees this refusal. **Migration:** handle `thinking_binding` by leaving the refused block out of the next request, or by asking the provider to drop such blocks: Anthropic's `thinking.block_binding.prefix_mismatch_behavior: "drop_block"`, which a request can set today by giving the whole `thinking` object in `providerParams`. **Release order:** a framework whose `invalid_request` handling shed this history (agent-framework's poison-history breaker does) should handle `thinking_binding` before a membrane release carrying this reaches its hosts; otherwise the refused block is resent every turn. **Unchanged:** `httpStatus` stays 400 (a 422 with the same text is read the same way), and `providerErrorCode` is the provider's own code, as before: `invalid_request_error` on Anthropic. Through OpenRouter's wrapper the code is the router's own, a number, so `providerErrorCode` is unset there. Every other 400 stays `invalid_request`, a context overflow stays `context_length`, and a 5xx whose text mentions the refusal stays a retryable `server` error.
