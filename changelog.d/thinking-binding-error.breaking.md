- **Consumers that switch exhaustively on `MembraneErrorType`, or act on `invalid_request`:** the public `MembraneErrorType` union gains a member, `thinking_binding`, for a 400 refusing a signed thinking block the request sent back ("Invalid `signature` in `thinking` block…"), which used to be typed `invalid_request`. Anthropic sends it for a block bound to a different conversation, or sent after what came before it changed (its block binding: seen live under `prefix_mismatch_behavior: "error"`, while under the default one account saw this 400 and another a silent drop), and for a block whose signature was altered, under every behavior. A `redacted_thinking` block's refusal is matched the same way, by analogy; it hasn't been seen. The request is well formed, and the error isn't retryable as it stands. **Who needs to act:** any code with an exhaustive `switch` over `MembraneErrorType`, or a `Record<MembraneErrorType, …>` lookup, which TypeScript now reports; and any consumer that acts on `invalid_request` as a malformed request, such as a breaker that sheds history over it, which no longer sees this refusal. A consumer that compares the type as a string, as agent-framework's breaker does, gets no compiler warning at all: the refusal just stops matching its `invalid_request` checks. **Migration:** handle `thinking_binding` by leaving the refused block out of the next request. For a binding refusal (a block from another conversation, or one whose earlier content changed), you can instead ask the provider to drop such blocks: Anthropic's `thinking.block_binding.prefix_mismatch_behavior: "drop_block"`, with the `thinking-binding-controls-2026-08-01` beta. On Anthropic's own API and on Bedrock a request can set it today by giving the whole `thinking` object in `providerParams`, with the beta in the Anthropic client's `defaultHeaders` or in Bedrock's `anthropic_beta`. An altered signature is refused under `drop_block` too, so leaving the block out is its only remedy. **Release order:** membrane types the refusal; it doesn't drop or re-mint blocks. A consumer whose `invalid_request` handling removed the refused block, by stripping thinking or dropping the message that carries it, stops doing that for this refusal. Handle `thinking_binding` before a release carrying this reaches your hosts, or the block is resent on every request. **Unchanged:** `httpStatus` stays 400 (a 422 with the same text is read the same way), and `providerErrorCode` is the provider's own code, as before: `invalid_request_error` on Anthropic. Through OpenRouter's wrapper the code is the router's own, a number, so `providerErrorCode` is unset there. Every other 400 is typed as before: `auth` or `context_length` where its reason, code or text says so, and `invalid_request` otherwise. A 5xx whose text mentions the refusal stays a retryable `server` error. **Siblings:** agent-framework doesn't handle `thinking_binding` yet; agent-framework#302 tracks it. context-manager's fallback for a carrier-bearing request reads the 400 status and the message, not the type, so it copes with the 400 as it is; a 422 refusal matches it only when its message says `invalid_request`. connectome-host's bug report lists the error types by name (`src/bug-report.ts`), so it needs the new member to name this one.
