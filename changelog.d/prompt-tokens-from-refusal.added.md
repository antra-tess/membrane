- `MembraneError.promptTokens`: for a `context_length` error, the request's input token count where the provider's refusal states one, as a number only. Anthropic states it in "prompt is too long: N tokens > M maximum" and "input length and `max_tokens` exceed context limit: N + K > M", Gemini in "The input token count (N) exceeds …", and OpenAI's long form in "… However, your messages resulted in N tokens."; OpenRouter passes on its upstream provider's. OpenAI's shorter and current forms, the Responses API's and Bedrock's state none, and leave it unset. It's read from the text the error's type is classified from: from a provider's body, the message fields membrane extracts from it, so an echo of the request beside those fields can't supply one. That text can hold more than the provider's message, and an echo in it does supply the count: a body that doesn't parse as JSON, or a string `error`, is taken whole as the message; and for a status-less Anthropic error whose body membrane doesn't recognise, or a Bedrock stream error with no message, the type and the count are read from a rendering of the body. `ErrorInfo` carries it, so copies made with `toErrorInfo` keep it.
