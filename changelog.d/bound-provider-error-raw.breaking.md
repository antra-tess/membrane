- **Code that reads a provider's fields from a `MembraneError`'s `rawError`:** past 16 KiB of JSON (UTF-8), `rawError` is now a summary in its place, `{ truncated, bytes | jsonBytes, sha256, head }`, where it was the value as serialized, so an echoed request no longer makes it as large as the body. An identical body stays recognizable by its hash. The summary keeps the request id under the keys it came in, `requestID`, `request_id`, `_request_id` and `headers['request-id']`, and no other field of the original. `classifyError` bounds the `rawError` it returns the same way.
  - **Who needs to act:** code that reads any other field from a `rawError` that large, such as the provider's body.
  - **Migration:** read the error's own fields, `type`, `httpStatus`, `providerErrorCode` and `retryAfterMs`, which are read from the whole body before the cut, or find the full body in your own log by its `sha256`.
  - **Unchanged:** a `rawError` within 16 KiB of JSON, or with no JSON form, is kept as serialized, as before. At each sibling's `main`, agent-framework and context-manager read no field of a `MembraneError`'s `rawError`, and connectome-host reads its request id, which the summary keeps, and its `status` only for an error with no `httpStatus`.
