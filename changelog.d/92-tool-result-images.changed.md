- **OpenAI, OpenAI-compatible, OpenRouter, and Gemini adapters:** `toolResultImages: 'auto' | 'media' | 'omit'` controls tool-image transmission and defaults to `auto`. Explicit `media` or `omit` wins. Otherwise, the first request needing tool-image conversion consults the caller's `ModelRegistry.getCapabilities(model)?.media.imageInput`, then adapter knowledge if the registry returns `undefined`. The adapter pins that decision, including omission, per effective model for its lifetime. Image-free calls neither fetch metadata nor freeze a decision. Membrane passes registry knowledge through `ProviderRequestOptions.getModelImageInput`, outside hook requests, semantic cache receipts, and provider JSON. **Adapter decorators:** forward this request option. An enumerable own Chat model override in `request.extra.model`, including a change from `beforeRequest`, selects the capability key when it is a string; any other value leaves the requested model as the key. The adapter captures override values once so getters and asynchronous lookup cannot separate the selected model from the sent model.
- **Automatic defaults:** Gemini sends media. OpenAI sends media except known text-only families (`o1-mini`, `o1-preview`, `o3-mini`, `gpt-3.5*`, `gpt-oss-*`, and original/text-only GPT-4 versions, including fine-tuned IDs of those bases). Registry lookup, pinned decisions, and wire output retain the full fine-tuned model ID. Generic OpenAI-compatible endpoints use omission placeholders unless the registry or explicit mode opts into media. OpenRouter sends media only when the model catalogue beside the adapter's `baseURL` (`https://openrouter.ai/api/v1/models` by default), asked with the headers its requests carry, key included, lists `image` in the model's `architecture.input_modalities`. Each OpenRouter adapter caches one catalogue snapshot, with a five-second limit covering fetch and body read. A model the catalogue doesn't list, or lists without input modalities, and every model after a failed lookup, select omission, and the adapter warns once per such model on `console.warn`, naming the model and the reason. A failed snapshot remains empty for that adapter, including later unseen models; registry knowledge can still decide an unresolved model. Create a new adapter to refresh the catalogue and model decisions. Concurrent first callers share resolution. Caller cancellation stops that caller's wait, while the shared lookup continues under its own bound; `timeoutMs` covers metadata plus inference.
- Normalized tool-result image bytes are sent as media or replaced with an explicit omission, rather than serialized as billed tool text. Tool-result media reaches OpenRouter as native tool content, OpenAI and OpenAI-compatible endpoints as labelled user images after the complete paired tool-result batch, and Gemini as inline media (inside function responses on Gemini 3, labelled sibling parts on older models and unversioned `-latest` aliases). Combined assistant replay keeps calls before results. Image-bearing helper envelopes keep results before sibling user text in every mode. Mixed text/image order and parallel pairing are retained. An image-bearing error result in media form opens with `[Tool result error]`, and Gemini sends it under `response.error`. Image omission and relocation preserve native non-image sibling parts. Chat tool images accept JPEG/PNG/GIF/WebP, as HTTP(S) references or validated inline data; Gemini accepts PNG/JPEG/WebP/HEIC/HEIF, as inline data only. Inline data is a base64 source or a base64 data URL, read as the URL parser reads it (surrounding whitespace ignored, parameters before `;base64` allowed). Only image bytes are ever omitted: bytes a transport can't take (an unsupported type, or a data URL that isn't base64) become an explicit omission. A source without bytes that a transport can't take as an image (a non-HTTP(S) URL on Chat, any URL on Gemini, or another source type such as a file path) is sent as the block's own JSON text, as main sent it, address and any other keys included. A recognized byte signature decides the type, overriding a misleading ingest label. Bytes declared as JPEG, PNG, GIF or WebP without that type's signature, which every such image opens with, are not sent as media; a declared HEIC/HEIF type, which no signature here covers, is taken as given. MCP-style `data` images and `generated_image` payloads in tool results have no media form here: they are replaced by the per-image notice rather than sent as base64 text, which put a 300KB screenshot into the prompt as ~400KB of text on every request while it stayed in history. Histories that carried such text shrink once. Models resolved to omission receive a per-image notice in place of image bytes (base64 sources and data URLs), and a source without bytes keeps the text form it had before. This prevents known text-only models from failing while images remain in history. Histories restored to media change request bytes, can incur a one-time prompt-cache miss, and bill vision tokens in place of placeholders.
- **Exported Chat helpers:** `toOpenAIMessages(messages, { toolResultImages: 'media' | 'omit' })` and `toOpenRouterMessages` default to `omit`. These synchronous helpers have no model/registry lookup. An explicit helper `media` choice produces caller-owned native media. Adapters can gate normalized tool results and native `role: 'tool'` images, by the same bytes rule: omission replaces an image's bytes with the notice, and a reference keeps the part's own JSON text. Such a native tool message now keeps its `tool_call_id`, which Chat conversion previously dropped along with the image, but OpenAI helper relocation produces ordinary user images whose tool provenance is lost. A later adapter `omit` choice cannot undo that relocation. Pass normalized tool results to the adapter for model-aware conversion. Whole native payload overrides (`extra.messages` on Chat adapters or `extra.contents` on Gemini) remain caller-owned passthrough outside conversion, validation, and capability gating. Replaced normalized images trigger neither lookup nor a pinned decision.
- Native `image_url` array blocks the caller writes into a user, assistant or system message, previously dropped by Chat conversion, are now sent after the same validation as tool images: HTTP(S) references and valid inline data are sent as images, inline bytes Chat can't take become an explicit omission, and any other reference (a local or malformed URL) is sent as the part's own JSON text, address included. Like normalized images in the same messages, they are the caller's explicit media and follow no capability decision, even when tool images are omitted. **A model without image input refuses every request while such a part stays in history**, as it already refuses a normalized image there, where Chat conversion used to drop the part silently; leave such parts out of history for such a model. This changes affected messages' bytes and cache prefixes.
- Generated image-omission notices describe only the particular image that was not shown: `[system: this image in the tool result was NOT shown to you.]`. #84's notice, on main but in no release, claimed that all tool results reach the model as text only, which could contradict image/audio media in sibling parts or results. **Deployments running main since #84 change bytes/cache prefixes once** where that notice is regenerated, including non-normalized MCP/generated-image fallbacks. Already-stored ordinary text containing the old notice is preserved. The image-byte omission safeguard itself is unchanged.
- Gemini always recovers `functionResponse.name` from the preceding tool call, with an explicit result name taking precedence and the call ID or `unknown` as fallback. This corrects image-free results too: affected histories take one upgrade-time byte/cache change. Earlier names stay stable when later images enter or leave history. Other image-free, omission-free requests keep their existing serialization.
- NativeFormatter uses the adapter's optional `toolResultImageMediaTypes` policy for nested tool-result images, so Gemini HEIC/HEIF history survives `Membrane.complete()` as well as streaming. Other transports keep their existing media-type policy. **Adapter wrappers:** forward `toolResultImageMediaTypes` to enable that history support. connectome-host's forwarding companion is merged in [anima-research/connectome-host#188](https://github.com/anima-research/connectome-host/pull/188); installed membrane versions still determine availability. The adapter also validates direct/live results. These changes are covered by mocked transports; the maintainer separately verified OpenRouter tool-message and relocated-user-image carriers live on vision models. Direct OpenAI, Gemini, and generic compatible live acceptance remains unverified here.
