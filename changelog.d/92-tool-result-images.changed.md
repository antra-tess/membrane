- **OpenAI, OpenAI-compatible, OpenRouter, and Gemini adapters:** `toolResultImages: 'auto' | 'media' | 'omit'` controls tool-image transmission and defaults to `auto`. Explicit `media` or `omit` wins. Otherwise, the first request needing tool-image conversion consults the caller's `ModelRegistry.getCapabilities(model)?.media.imageInput`, then adapter knowledge if the registry returns `undefined`. The adapter pins that decision, including omission, per effective model for its lifetime. Image-free calls neither fetch metadata nor freeze a decision. Membrane passes registry knowledge through `ProviderRequestOptions.getModelImageInput`, outside hook requests, semantic cache receipts, and provider JSON. **Adapter decorators:** forward this request option. Enumerable own Chat model overrides in `request.extra.model`, including changes from `beforeRequest`, select the capability key. The adapter captures override values once so getters and asynchronous lookup cannot separate the selected model from the sent model.
- **Automatic defaults:** Gemini sends media. OpenAI sends media except known text-only families (`o1-mini`, `o1-preview`, `o3-mini`, `gpt-3.5*`, `gpt-oss-*`, and original/text-only GPT-4 versions, including fine-tuned IDs of those bases). Registry lookup, pinned decisions, and wire output retain the full fine-tuned model ID. Generic OpenAI-compatible endpoints use omission placeholders unless the registry or explicit mode opts into media. OpenRouter sends media only when the public `https://openrouter.ai/api/v1/models` catalogue lists `image` in the model's `architecture.input_modalities`. Each OpenRouter adapter caches one catalogue snapshot, with a five-second limit covering fetch and body read. Unknown models and lookup failures select omission, and the adapter warns once per such model on `console.warn`, naming the model and the reason (the lookup's failure, or that the catalogue doesn't list the model). A failed snapshot remains empty for that adapter, including later unseen models; registry knowledge can still decide an unresolved model. Create a new adapter to refresh the catalogue and model decisions. Concurrent first callers share resolution. Caller cancellation stops that caller's wait, while the shared lookup continues under its own bound; `timeoutMs` covers metadata plus inference.
- Normalized tool-result image bytes are sent as media or replaced with an explicit omission, rather than serialized as billed tool text. Tool-result media reaches OpenRouter as native tool content, OpenAI and OpenAI-compatible endpoints as labelled user images after the complete paired tool-result batch, and Gemini as inline media (inside function responses on Gemini 3, labelled sibling parts on older models and unversioned `-latest` aliases). Combined assistant replay keeps calls before results. Image-bearing helper envelopes keep results before sibling user text in every mode. Mixed text/image order and parallel pairing are retained. An image-bearing error result in media form opens with `[Tool result error]`, and Gemini sends it under `response.error`. Image omission and relocation preserve native non-image sibling parts. Chat tool images accept JPEG/PNG/GIF/WebP, as HTTP(S) references or validated inline data URLs; Gemini accepts PNG/JPEG/WebP/HEIC/HEIF, as inline base64 data. Only image bytes are ever omitted: bytes a transport can't take (an unsupported type, or a data URL on Gemini) become an explicit omission. A source without bytes that a transport can't take as an image (a non-HTTP(S) URL on Chat, any URL on Gemini, or another source type such as a file path) is sent as the block's own JSON text, as main sent it, address and any other keys included. Recognized bytes override misleading ingest labels before MIME acceptance. Non-normalized MCP/generated-image payloads retain #84's omission safeguard. Models resolved to omission receive a per-image notice in place of image bytes (base64 sources and data URLs), and a source without bytes keeps the text form it had before. This prevents known text-only models from failing while images remain in history. Histories restored to media change request bytes, can incur a one-time prompt-cache miss, and bill vision tokens in place of placeholders.
- **Exported Chat helpers:** `toOpenAIMessages(messages, { toolResultImages: 'media' | 'omit' })` and `toOpenRouterMessages` default to `omit`. These synchronous helpers have no model/registry lookup. An explicit helper `media` choice produces caller-owned native media. Adapters can gate normalized tool results and native `role: 'tool'` images; such a native tool message now keeps its `tool_call_id`, which Chat conversion previously dropped along with the image, but OpenAI helper relocation produces ordinary user images whose tool provenance is lost. A later adapter `omit` choice cannot undo that relocation. Pass normalized tool results to the adapter for model-aware conversion. Whole native payload overrides (`extra.messages` on Chat adapters or `extra.contents` on Gemini) remain caller-owned passthrough outside conversion, validation, and capability gating. Replaced normalized images trigger neither lookup nor a pinned decision.
- Native user `image_url` array blocks, previously dropped by Chat conversion, are now sent after the same URL/inline MIME validation as tool images. HTTP(S) references remain references; local, malformed, and unsupported inline sources become omissions. This changes affected user-message bytes and cache prefixes. Ordinary user images remain explicit media even when tool images are omitted.
- Generated image-omission notices describe only the particular image that was not shown: `[system: this image in the tool result was NOT shown to you.]`. #84's notice, on main but in no release, claimed that all tool results reach the model as text only, which could contradict image/audio media in sibling parts or results. **Deployments running main since #84 change bytes/cache prefixes once** where that notice is regenerated, including non-normalized MCP/generated-image fallbacks. Already-stored ordinary text containing the old notice is preserved. The image-byte omission safeguard itself is unchanged.
- Gemini always recovers `functionResponse.name` from the preceding tool call, with an explicit result name taking precedence and the call ID or `unknown` as fallback. This corrects image-free results too: affected histories take one upgrade-time byte/cache change. Earlier names stay stable when later images enter or leave history. Other image-free, omission-free requests keep their existing serialization.
- NativeFormatter uses the adapter's optional `toolResultImageMediaTypes` policy for nested tool-result images, so Gemini HEIC/HEIF history survives `Membrane.complete()` as well as streaming. Other transports keep their existing media-type policy. **Adapter wrappers:** forward `toolResultImageMediaTypes` to enable that history support. connectome-host's forwarding companion is merged in [anima-research/connectome-host#188](https://github.com/anima-research/connectome-host/pull/188); installed membrane versions still determine availability. The adapter also validates direct/live results. These changes are covered by mocked transports; the maintainer separately verified OpenRouter tool-message and relocated-user-image carriers live on vision models. Direct OpenAI, Gemini, and generic compatible live acceptance remains unverified here.
