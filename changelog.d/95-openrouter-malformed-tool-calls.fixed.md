- OpenRouter, OpenAI and OpenAI-compatible: a malformed `tool_calls` entry in a response no longer fails the whole response (antra-tess/membrane#95). Before, `tool_calls: [{}]` threw "Cannot read properties of undefined (reading 'name')" and the text and usage were lost. Now an entry without a non-empty string `function.name` is skipped, on the complete and stream paths alike, with one warning per response that does not log provider content, and the rest of the message is kept. A streamed call that has an id but never got a name is skipped the same way instead of becoming a `tool_use` named `''`. When `finish_reason` is `tool_calls` but no call is left to run, `stopReason` is `end_turn` instead of `tool_use`, so a caller that runs tools on `tool_use` is not handed none; `providerStopReason` still carries `tool_calls`. Well-formed calls are unchanged.
