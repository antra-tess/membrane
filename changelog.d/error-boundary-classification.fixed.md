- Provider errors are now classified at the fetch boundary, where the HTTP response is still live: status is preserved verbatim (a 503 is a 503, not a fabricated 500; 402/403/404/413/422 are no longer erased into `unknown` with no status), `retry-after` is read from the response headers (and from google's body `retryDelay`), and the provider's own error type/code reaches the caller as `providerErrorCode`.
- `insufficient_quota` and its billing siblings are no longer reported as retryable rate limits: a 429 whose provider code says the account is out of credit is non-retryable. HTTP failures and HTTP-200 SSE error payloads share this classifier. SSE error statuses in 400–599 take precedence over conflicting descriptive tokens; a transport 200 or arbitrary numeric provider code leaves symbolic-code classification available. Numeric code strings no longer hide a symbolic error type. Frame diagnostics, raw evidence, and retry hints are retained. An explicit SSE 400 now yields a typed non-retryable `invalid_request` rather than a bare `Error`; truly unclassified payloads yield an `unknown` MembraneError with their evidence.
- The per-adapter substring tables that re-derived a classification from a rendered error string are gone; `classifyError` remains as the last resort for non-HTTP throwables only, with narrowed patterns (a body containing "generated"/"moderate" is no longer promoted to a rate limit, and an internal `TypeError` mentioning "maximum" is no longer reported as a provider context-length error).
- Preserve the retryable network classification for Node/browser `fetch failed` and `Failed to fetch` errors. Anthropic gateway metadata is a fallback for an unresolved classification, so it cannot override an established auth, quota, or rate-limit result. Bedrock errors carry the same model ID and stream identity reported by `onRequest`, alongside the existing body.
- A transient 5xx whose body happens to mention "context", "too long" or "token" stays a retryable server error on every adapter — the status guard that previously existed only in the Anthropic adapter now holds at the shared boundary, bedrock's bare `token` match included.
- `isOverloadedError` matches a status-shaped `529` only, so an ordinary retryable error whose text merely contains those digits ("timeout after 5290 ms", "req-98529abc") is no longer put on the ~10-minute overloaded schedule.
- Original PR verification used live testing: invalid-model 404 and invalid-key 401/400 against Anthropic (`claude-haiku-4-5-20251001`), OpenAI (`gpt-4o-mini`) and Google (`gemini-3.5-flash-lite`), each returning its status and provider error code verbatim (`not_found_error` / `model_not_found` / `NOT_FOUND`), plus one successful call per provider. Mock-only: 429 rate limits, `retry-after` headers, 402/413/422/5xx, openai-compatible, openai-completions, OpenRouter and Bedrock.
- The current composition and review corrections were verified locally with scripted/mocked providers; the preceding live results remain attributed to the original contributor.
