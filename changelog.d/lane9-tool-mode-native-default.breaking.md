- **Default/native Membrane callers:** automatic tool mode selects native when the active formatter supports it across `complete()`, `stream()`, and `streamYielding()`, including tool-free calls. `AnthropicXmlFormatter` in resolved native mode now builds a real native conversation rather than an assistant-prefill transcript with attached tools. Native paths share formatter-backed normalization, media handling, context prefixes, participant labels, custom stops, and provider parameters. The tool loop retains its separate floating-cache placement. **Request bytes and cache prefixes change** for the former default/XML representation and for native paths that previously dropped caller fields. Native stream/yielding preserve opaque message metadata by passing their prompt-serialization input in adapter options rather than adding it to semantic requests/receipt hashes. The prior complete/XML and configured Responses metadata contracts remain unchanged. To keep transcript-prefill behavior, select `toolMode: 'xml'` on a compatible formatter/transport/model. Explicit request mode takes precedence over the active formatter's explicitly configured mode, then its declared capabilities.
- **Native streaming callers, stop sequences:** native `stream()` and `streamYielding()` apply the request's stop sequences to visible text themselves, as they stand after `beforeRequest` hooks. The accepted output ends at the first stop whether or not the provider applied it: the Responses API has no stop parameter, Chat Completions drops it for some models and sends at most four, Gemini sends five, and a custom adapter need send none. No chunk, block event, returned block or replayed Responses item carries the stop or anything after it, however the provider chunks the text or divides it into blocks. Text that could still begin a stop is held until it settles, and text a provider reports only in its returned output is held to the same stops. With stops configured, a block event is reported once a chunk follows it or the stream ends, so a trailing tool call's events arrive when the stream ends rather than as they stream. The response reports `stopReason: 'stop_sequence'` with the stop. A tool call after the stop is neither returned nor run. Thinking is never scanned, a non-text block ends a stretch of visible text, and the provider's own stream runs to its end, so usage and `raw` are the provider's. Explicit XML keeps its parser-aware stop handling, and `complete()` still returns what the provider returned. Covered with the actual Anthropic and Responses adapters over synthetic streams.
- **`prefillUserMessage` in native mode:** when a native conversation needs a synthetic leading user turn (after a `contextPrefix`, before assistant-first history, or after role repair moved a block to the front), that turn carries `prefillUserMessage`. Without it, the turn stays `[continuing]`.
- **Formatter authors:** declare both required booleans `supportsNativeTools` and `supportsXmlTools`. Missing JavaScript declarations now fail explicitly. False native support does not imply XML support; a tool-bearing request using an unsupported selected carrier fails before HTTP instead of silently losing tools. `CompletionsFormatter` supports neither tool carrier. This supersedes the unmerged PR's `buildsAssistantMessagePrefill` flag: parser prefill, a manufactured assistant prefix, and actual transport prefill are different facts.
- **Message-adapter callers and decorators:** built-in message transports check the final converted model/body, including post-hook/native overrides, against the assistant-prefill capability table. Known-incompatible tails fail with non-retryable `unsupported`, naming the selected formatter when called through Membrane. XML streaming runners also declare their future continuation requirement, so rejection can precede the first tool round; plain and image continuations are checked again. Native mode preserves caller-authored assistant-ended history rather than inventing a user turn. `ProviderRequestOptions.requestContext` carries the selected carrier and protocol facts outside provider JSON/receipts; decorators must forward options. Actual prompt transports, including renamed `OpenAICompletionsAdapter` instances, remain exempt from the Messages-prefill rule. Nonempty native tool lists that a prompt adapter would discard are rejected, including `request.tools` and `extra.tools`/`providerParams.tools`. On `OpenAICompletionsAdapter`, caller-owned XML `providerParams.prompt` content remains usable with an XML-capable formatter and XML mode. The Images adapter instead reports a tool-capable transport or omission as its remedy.
- **Native cache-budget callers:** Membrane's shared native build delegates membrane-owned budgets to its existing final post-hook clamp; CM-owned markers remain fail-loud. This changes `NativeFormatter`/`complete()`'s earlier message-only over-budget refusal into the same final policy used by native streaming. Standalone `NativeFormatter.buildMessages()` checks the complete messages/system/tools budget by default. Only callers owning a later complete-request check should set `BuildOptions.deferCacheBudgetCheck: true`; it never disables CM-owned assertions.
- The prefill table recognizes dotted OpenRouter versions, `bedrock:` aliases, dated/profile/ARN IDs, and Vertex suffixes. The original August measurements and the maintainer's September re-measurement remain attributed to their sources; Opus 5 is now correctly labelled measured, while Mythos entries remain family inferences. This correction's transport tests are mocked.

- Native tool calls restore names against the declared definitions instead of treating every double underscore as a colon. This preserves literal double-underscore names in complete, stream, and yielding calls. NativeFormatter rejects definitions whose encoded names collide before dispatch.

- **Native complete and plain-completion callers:** XML-looking response text is no longer interpreted as a tool invocation. Native structured tool blocks remain supported. XML tool decoding, stop-tag reconstruction, and diagnostics follow the selected XML-capable formatter/protocol; plain CompletionsFormatter output stays text across complete, streaming, yielding, and partial/aborted responses. To retain textual XML tool decoding, use an XML-capable formatter and `toolMode: 'xml'`. Plain paths retain provider-native thinking as structured blocks rather than adding XML wrappers.

- **Plain and native streaming callers:** provider thinking deltas remain typed and non-visible instead of entering a plain text parser. Received signatures and redacted blocks survive partial responses. Plain `rawAssistantText` contains visible text, while thinking stays in typed content. Native aborted responses now include typed `partialContent` from completed rounds and from what the current round received: its text and thinking, and each block the provider finished, including a finished tool call, which is listed but not run. A tool call whose arguments never finished is left out. Once the provider has returned a round, every block it returned counts as received, so a callback that aborts after the stream keeps them. An abort thrown from a callback while a single-final provider (Responses) is still reporting its finished blocks ends that call before it returns, and a finished tool call reported there is not kept; native raw chunk accumulation is unchanged. Explicit XML keeps its tagged protocol. Covered with actual Anthropic and Bedrock adapters over synthetic streams, including interrupted transport reads, plus the compatible adapter’s separately reported reasoning.

- **Custom formatter authors and decorators:** streamed plain responses can parse visible text spans around native thinking. Update prefix-sensitive or whole-response-sensitive `parseContentBlocks(content, tools?, context?)` implementations to honor the optional third argument, `ContentParseContext { visibleText, offset }`. Forward it through decorators. Merely accepting the optional argument does not preserve a whole-response assumption. Literal, span-independent parsers need no behavioral change. Built-in CompletionsFormatter now trims only the complete response's leading whitespace; NativeFormatter distinguishes a wholly blank response from internal whitespace-only spans. Whole-response calls without context and the second tool-schema argument keep their existing semantics.
